# PLAN.md — `numpy-lm-course`: an interactive course for building a language model from scratch in NumPy

> **For Claude Code.** This is the full spec for a project you will build in phases. Read the whole file before you start. Build **Phase 1 only**, then stop and ask the learner to review it (see §12). Do not skip ahead.

---

## 0. One-paragraph summary

Build a hybrid learning system that teaches one learner to build a language model from scratch in **pure NumPy**, in three stages: (1) an MLP character model, (2) a small character-level transformer, (3) a subword (BPE) transformer, with an autograd interlude between stages 1 and 2. It has two halves. A **local web course** (a static site served from the repo) teaches each lesson: concept, derivation, think-questions, a hint ladder, and a gated solution. A **local code workspace** holds a stub file for each lesson, plus `pytest` tests that check the learner's implementation and a CLI (`python -m course ...`) that runs checks and tracks progress. The learner reads a lesson on the site, writes the code in the stub, runs `python -m course check <lesson>`, and only then reveals the reference solution.

---

## 1. The learner (design everything around this)

- A student heading toward computer science / AI. Comfortable with Python and basic NumPy. Has studied backprop, RNNs, CNNs and transformers conceptually, and has hand-built small networks (e.g. a jamo-level GRU morphological analyzer in NumPy).
- **Prefers building things himself and understanding them** over black boxes. No pretrained models, no PyTorch, and no autograd libraries in any learner-facing code.
- Hardware: RTX 4070 Super (12GB), DDR5 32GB RAM. **Everything runs on the CPU via NumPy.** Currently on Windows, planning a Linux dual-boot. **All code must be cross-platform** (use `pathlib`, no shell-specific scripts, no hardcoded `/` or `\`).
- Teaching preferences (these are requirements, not suggestions):
  1. **One step at a time.** Small lessons. The learner moves on when ready.
  2. **Never skip steps in math.** Derive every formula from definitions; no formula should "appear out of nowhere". Show intermediate lines.
  3. **Explain every symbol and every piece of notation the first time it appears** (each lesson has a notation box).
  4. **Concrete examples constantly**: tiny worked examples with actual numbers (e.g. the string `"hello"`, k = 3, a 2×3 matrix).
  5. **Nudge, don't tell.** Think-questions first, then a 3-level hint ladder, and the code only when the learner asks for it.
  6. Math must **always render correctly**. Broken math is a bug.
  7. Clean formatting, with length matched to the content. No filler.
- Course language: **English** by default. Keep all learner-facing text in `lessons/` so it could be translated to Korean later (ask the learner in Phase 1, see §13).

## 2. Goals and non-goals

**Goals**
- The learner implements every forward pass, every backward pass, the optimizers, the tokenizer and the training loops himself.
- Each lesson ends with an automated check that tells him precisely what is wrong (shape, dtype, values, gradients).
- Stage milestones ("boss checks") with concrete numeric targets.
- Works fully offline after setup (vendor the JS libraries; dataset downloads are one-time).

**Non-goals**
- No PyTorch, JAX, TensorFlow, autograd, CuPy or numba anywhere in `workspace/` or `solutions/`.
- No GPU code.
- No user accounts, servers beyond `http.server`, databases or frameworks (no React/Vue/build chains). Plain HTML/CSS/JS plus a Python build script.

## 4. Learner workflow (the loop every lesson follows)

1. `python -m course serve` → opens the site in the browser (http://localhost:8000), with progress synced from `progress.json`.
2. The learner reads the lesson: goal → concept → think-questions (types an answer, then reveals the model answer) → hint ladder as needed.
3. He opens the stub file shown in the lesson's "Your attempt" box and implements the function(s).
4. `python -m course check s1-l01` → runs that lesson's tests and prints a friendly pass/fail with teaching messages. On a pass it updates `progress.json` and prints `Next: s1-l02 — Embedding lookup`.
5. The solution section on the site unlocks after a pass (or after an explicit "show anyway" click, which is recorded).
6. Optional: "Break it" experiments in `notebooks/`.

- Math: inline `$...$`, display `$$...$$` on its own lines. **Every display formula on its own line(s), with intermediate derivation lines.**
- Every array in prose carries its shape: `x` `(B, k)`.

## 6. Content style guide (applies to every lesson)

1. **Derive, don't state.** Example: for the cross-entropy gradient, start from $L = -\log p_y$ and $p_i = e^{z_i}/\sum_j e^{z_j}$, then differentiate case by case ($i = y$ and $i \ne y$), then combine, then extend to the batch mean. Show every line.
2. **Numbers first.** Each concept section has a worked example with real numbers that the learner could verify by hand (e.g. logits `[2.0, 1.0, 0.1]` → softmax values to 3 decimals → loss).
3. **Shapes everywhere.** Before any matrix product, state both shapes and the result shape. Teach the "shape-matching trick" for backward passes (lesson s1-l06), then reuse it.
4. **Think-questions probe the why**, not recall: "Why split by position rather than shuffling?", "What should the loss be at initialization, and why?"
5. **Hint ladder:** level 1 = which idea; level 2 = which NumPy feature (e.g. "fancy indexing", "`np.add.at`", "broadcasting a column against a row"); level 3 = pseudocode.
6. **Break it** must name the expected observation (e.g. "the loss becomes `nan` at step ~1"), so the learner knows what to look for.
7. Tone: friendly, direct, concise. No hype. Short paragraphs.
8. Optional "Your projects" callouts where genuinely relevant (e.g. in s3: running BPE over Korean text, or over jamo as in the learner's Korean_NLP project). At most one per stage.

## 7. Curriculum — per-lesson spec

For each lesson: **objectives**, **must-cover concepts/derivations**, **stub signatures**, **tests**, **break-it**. Conventions: row-vector convention `x @ W`; `float32` for all model math; `float64` only in gradient checks; `rng = np.random.default_rng(seed)` is always passed explicitly (no global RNG).

### Stage 0 — Setup

**s0-l00 Setup & NumPy pitfalls**
- Objectives: environment works; understand float32 vs float64; measure the machine's matmul GFLOPS.
- Cover: NumPy's float64 default (`np.random.randn`, `np.zeros`, Python floats) and silent upcasting; `np.show_config()` (BLAS backend); views vs copies; contiguity.
- Stub: `def to_f32(*arrays) -> tuple`, `def matmul_gflops(n: int, reps: int, rng) -> float`.
- Tests: dtype preservation; GFLOPS returns a positive float.
- Break it: add a float64 scalar array to a float32 array and inspect the dtype.
- `course check s0-l00` also prints the measured GFLOPS and stores it in `progress.json` (used later for time estimates).

### Stage 1 — MLP character language model (Bengio 2003 style)

Dataset: Tiny Shakespeare (~1.1M chars, V = 65), split 90/10 by position.

**s1-l01 Vocabulary, encoding, batches**
- Cover: char → int mappings; why sort the vocabulary (reproducibility); dtype choice (V = 65 fits `uint8`; convert to `int64` for indexing); why split by position (overlapping windows leak between train and val if shuffled); count of pairs from length n with context k is n − k; precomputing all pairs vs random sampling (memory: n·k ints; random sampling scales to stage 3); vectorized window gather via broadcasting `i[:, None] + np.arange(k)[None, :]`.
- Worked example: `"hello"`, k = 3 → `(h e l → l)`, `(e l l → o)`.
- Stubs: `build_vocab(text) -> (stoi: dict, itos: list)`, `encode(text, stoi) -> np.ndarray`, `decode(ids, itos) -> str`, `train_val_split(data, frac=0.9) -> (train, val)`, `get_batch(data, B, k, rng) -> (x: (B,k) int64, y: (B,) int64)`.
- Tests: round trip; vocab sorted and unique; split sizes and order; batch shapes/dtypes; for every row, `y[r] == data[start_r + k]` and `x[r] == data[start_r:start_r+k]` (reconstruct starts by a seeded rng); all indices in range; speed test (B = 4096 must run under a generous time bound, which catches Python loops).
- Break it: shuffle before splitting, then (later, in l12) observe an optimistic val loss.

**s1-l02 Embedding lookup (forward)**
- Cover: one-hot vector × matrix = row selection (derive with V = 4, e = 2, actual numbers); why lookup beats one-hot matmul (cost); `C[x]` on a 2D index array gives `(B, k, e)`; flatten to `(B, k·e)`.
- Stubs: `embedding_forward(C, x) -> (emb (B,k,e))`, `flatten_context(emb) -> (B, k*e)`.
- Tests: equals the one-hot matmul result; shapes; dtype float32.
- Break it: compare the one-hot matmul time vs indexing for V = 65 and V = 8000.

**s1-l03 Linear layer and tanh (forward)**
- Cover: $y = xW + b$ with shapes $(B,n)(n,m) + (m,)$, bias broadcasting; tanh range and saturation; why a nonlinearity is needed (two linear layers collapse into one — show the algebra).
- Stubs: `linear_forward(x, W, b) -> (out, cache)`, `tanh_forward(x) -> (out, cache)`.
- Tests: values vs a direct computation; shapes; the cache contains what backward needs.
- Break it: remove tanh, train later, and compare (link forward to l10).

**s1-l04 Softmax and cross-entropy (stable)**
- Cover: softmax definition; overflow with `exp(1000)`; derive shift invariance $\mathrm{softmax}(z) = \mathrm{softmax}(z - c)$; log-sum-exp; $L = -\frac{1}{B}\sum_b \log p_{b, y_b}$; meaning of the loss value; uniform-guess loss $\ln V$ ($\ln 65 \approx 4.17$, derived).
- Stubs: `softmax(logits) -> probs`, `cross_entropy(logits, y) -> (loss: float, cache)`.
- Tests: rows sum to 1; matches the naive version on small logits; no nan/inf with logits ~1e4; uniform logits give `ln V`.
- Break it: remove the max-subtraction and feed large logits → `nan`.

**s1-l05 Deriving the cross-entropy gradient**
- Cover: full derivation of $\partial L / \partial z_i = p_i - \mathbb{1}[i = y]$ for one example (the quotient rule, cases $i=y$ and $i \ne y$), then the $1/B$ factor for the batch mean. Worked numeric example. Intuition: "push down every wrong class by its probability, pull up the right one by $(1-p_y)$".
- Stub: `cross_entropy_backward(cache) -> dlogits (B, V)`.
- Tests: vs a numerical gradient (tests/helpers gradcheck in float64); rows of dlogits sum to 0 (explain why in think).
- Break it: forget the `1/B` and see that the gradient scales with batch size.

**s1-l06 Backward through linear and tanh**
- Cover: derive $dW = x^\top\,dout$, $db = \sum_b dout_b$, $dx = dout\,W^\top$ using index notation on a 2×2 example with numbers; then the **shape-matching trick** as a sanity check; $\frac{d}{dx}\tanh x = 1 - \tanh^2 x$ derived from the definition; the chain rule as "multiply local derivative by upstream gradient".
- Stubs: `linear_backward(dout, cache) -> (dx, dW, db)`, `tanh_backward(dout, cache) -> dx`.
- Tests: gradcheck each; shapes equal the parameter shapes.
- Break it: compute `db` without summing over the batch → shape error; explain.

**s1-l07 Embedding backward**
- Cover: gradient flows only to the rows that were looked up; repeated indices must **accumulate**; why `dC[x] += demb` silently drops duplicates (buffered fancy-index assignment) — demonstrate with x = [1, 1]; `np.add.at` as the fix. Also un-flatten `(B, k·e)` → `(B, k, e)`.
- Stub: `embedding_backward(demb, x, V) -> dC (V, e)`.
- Tests: repeated indices accumulate correctly; gradcheck.
- Break it: use `dC[x] += ...` and watch the test fail.

**s1-l08 Gradient checking**
- Cover: the centered difference $\frac{f(\theta+\epsilon)-f(\theta-\epsilon)}{2\epsilon}$, why centered beats one-sided (derive the error orders with Taylor expansion), relative error $\frac{|a-n|}{\max(|a|,|n|,\delta)}$, float64 requirement, thresholds (<1e-7 great, <1e-5 ok, >1e-3 a bug), spot-checking random entries for big tensors.
- Stub: `gradcheck(f, params: dict, grads: dict, eps=1e-5, n_checks=20, rng) -> dict[name, max_rel_err]`.
- Tests: it passes on a correct function and flags a deliberately broken gradient.
- Break it: run in float32 and watch the "errors" from precision alone.

**s1-l09 Assemble the MLP, initialize, overfit one batch**
- Cover: params `C (V,e), W1 (k·e,h), b1 (h), W2 (h,V), b2 (V)`; param count formula, evaluated for k=8, e=24, h=512 (≈134K); forward/backward as a composition of the earlier pieces; initialization: scale `W1` by $1/\sqrt{\text{fan\_in}}$ (derive the variance argument briefly) and make `W2` small so the initial loss ≈ $\ln V$ (think: why?); tanh saturation check (fraction of |h| > 0.97); overfitting one batch as a correctness test.
- Stubs: `init_params(V, k, e, h, rng) -> dict`, `forward(params, x, y) -> (loss, cache)`, `backward(cache) -> grads dict`, `count_params(params) -> int`.
- Tests: initial loss within ±0.15 of ln 65; full-model gradcheck; overfit 32 examples to loss < 0.05 within 1000 SGD steps (seeded).
- Break it: init `W2` with std 1 → initial loss ≫ 4.17, plus a "hockey stick" curve.

**s1-l10 Training loop + SGD**
- Cover: minibatch SGD update $\theta \leftarrow \theta - \eta\,\nabla_\theta L$; why minibatches (noise, speed); logging; plotting loss (smoothed); steps vs epochs.
- Stubs: `sgd_step(params, grads, lr)`, and the `train_mlp.py` skeleton with TODOs for the loop (config dict at top).
- Tests: on a fixed seed and tiny config, loss after 200 steps < loss at step 0 by a margin; params are updated in place (or returned consistently, decide and document).
- Break it: lr too high (diverges), too low (crawls); show both curves.

**s1-l11 Adam**
- Cover: momentum as an exponential moving average (expand $m_t$ for t=1,2,3 with numbers); second moment $v_t$; **bias correction derived** (at t=1, $m_1 = (1-\beta_1)g$, so divide by $1-\beta_1^t$); the update $\theta \mathrel{-}= \eta\,\hat m/(\sqrt{\hat v}+\epsilon)$; why per-parameter step sizes help.
- Stub: `class Adam: __init__(params, lr, betas=(0.9,0.999), eps=1e-8); step(grads)`.
- Tests: matches hand-computed values for 3 steps on a 2-element parameter; state shapes.
- Break it: drop the bias correction and watch the early steps on a fresh run.

**s1-l12 Evaluation, LR sweep, hitting the target**
- Cover: `estimate_loss` over many val batches (variance of single-batch estimates); train/val gap = overfitting signal; an LR range test (log-spaced LRs, short runs, plot); LR decay; `results.json` logging.
- Stubs: `estimate_loss(params, data, B, k, n_batches, rng) -> float`; complete `train_mlp.py`.
- Tests: estimate_loss is deterministic under a seed; equals the mean of the per-batch losses.
- **s1-boss** (`lessons/s1/boss.md`, `course check s1-boss`): reads `runs/s1/results.json`; passes if val loss ≤ 2.10 (document it as a ballpark target; tune to what the reference solution actually reaches on CPU, see §11). Also prints the training time.

**s1-l13 Sampling**
- Cover: sampling from a categorical distribution (`rng.choice(V, p=...)`, or the cumulative-sum method — derive it); temperature $p_i \propto e^{z_i/\tau}$ and the limits τ→0 (argmax) and τ→∞ (uniform), with numeric examples; seeding with a prompt; sliding the context window.
- Stub: `sample(params, itos, stoi, prompt, n_chars, temperature, rng) -> str`.
- Tests: the empirical frequency of samples from fixed logits matches softmax within tolerance (10K draws); temperature → small gives argmax; output length.
- Break it: temperature 0.3 vs 1.0 vs 2.0 on the trained model.

### Interlude A — Autograd engine (NumPy)

**a-l01 The Tensor class**
- Cover: the computational graph; a node stores `data` (float32 ndarray), `grad`, `_prev` (parents), `_backward` (closure); why gradients **accumulate** (`+=`) when a node is used twice (derive with $f = x \cdot x$).
- Stubs: `class Tensor` with `__init__`, `__add__`, `__mul__`, `zero_grad`.
- Tests: scalar cases; reuse of a node.

**a-l02 Broadcasting-aware ops**
- Cover: **unbroadcasting**: if the forward broadcast `b (m,)` to `(B, m)`, its gradient must be summed over the broadcast axes (derive with a 2×3 example); a general `unbroadcast(grad, shape)` helper; ops: `matmul`, `tanh`, `sum`, `mean`, `reshape`, `__getitem__`-style embedding gather (backward via `np.add.at`), and fused `cross_entropy` (reuse the s1-l05 derivation).
- Stubs: `unbroadcast`, op functions/methods.
- Tests: gradcheck per op, including broadcasting cases.

**a-l03 backward(): topological sort**
- Cover: why order matters; DFS topological sort; seeding `grad = 1` at the loss; zeroing grads between steps.
- Stub: `Tensor.backward()`.
- Tests: diamond-shaped graph; a deep chain; repeated backward without zeroing accumulates (documented behavior).

**a-l04 Rebuild the MLP on the engine**
- Cover: the same model, now written as a forward pass only.
- Stub: `autograd/mlp.py` (`MLP` with `parameters()`, `__call__`).
- Tests: with the same seed and init, **loss and all gradients match** the stage-1 manual implementation (`allclose`, rtol 1e-5).
- Break it: forget `zero_grad` → gradients keep growing.

### Stage 2 — Character-level transformer (on the autograd engine)

Config target: d = 128, heads = 4, L = 4, T = 128 (≈0.8M params; derive via $12Ld^2 + Vd + Td$).

**s2-l01 Token + positional embeddings; next-token targets at every position**
- Cover: inputs `(B, T)` and targets shifted by one, `(B, T)`; every position is a training example (T signals per sequence — think question); learned positional embeddings `(T, d)` added to token embeddings; shapes.
- Stubs: `get_batch_seq(data, B, T, rng)`, `Embeddings` module.
- Tests: target alignment; shapes; gradcheck.

**s2-l02 LayerNorm (forward + backward)**
- Cover: mean/variance over the last axis, $\hat x = (x-\mu)/\sqrt{\sigma^2+\epsilon}$, $\gamma,\beta$; **full backward derivation** step by step (it is the hardest derivation so far: go slowly, use a 3-element numeric example, and show the final compact form $dx = \frac{1}{\sigma}\left(d\hat x - \overline{d\hat x} - \hat x\,\overline{d\hat x \odot \hat x}\right)$ only after deriving it).
- Stub: `layernorm` op with a custom backward.
- Tests: output mean ≈ 0 / var ≈ 1 per row; gradcheck.

**s2-l03 GELU**
- Cover: the tanh approximation; derivative derived; GELU vs ReLU (plot).
- Stub: `gelu` op. Tests: values vs the formula; gradcheck.

**s2-l04 Single-head attention**
- Cover: Q, K, V projections; scores $QK^\top$ `(B, T, T)`; **why divide by $\sqrt{d_h}$** — derive Var(q·k) = d_h for unit-variance entries; softmax over the key axis; output $PV$; **softmax backward derived**: $dS = P \odot (dP - \mathrm{rowsum}(dP \odot P))$; numeric 3-token example.
- Stub: `attention_single_head(x, Wq, Wk, Wv)` (op or composed from engine ops; if composed, also implement a fused softmax op with the derived backward).
- Tests: shapes; gradcheck; scaling test (without the √d_h scale, the softmax saturates at large d_h).

**s2-l05 Causal mask**
- Cover: why the model must not see the future; fill masked scores with a large negative number before softmax (float32-safe value, not −inf arithmetic issues; explain); a lower-triangular mask.
- Stub: add `causal=True` support.
- Tests: **perturbation test**: change tokens at positions > t and check the output at t is unchanged; rows of P sum to 1 with zeros above the diagonal.

**s2-l06 Multi-head attention**
- Cover: split d into h heads of d_h; reshapes and transposes `(B,T,d) → (B,h,T,d_h)` and back; one fused QKV matmul; output projection.
- Stub: `MultiHeadAttention` module.
- Tests: matches a per-head loop reference; gradcheck on a tiny config.

**s2-l07 Transformer block + full model**
- Cover: pre-LN residual block: `x = x + attn(ln1(x))`, `x = x + mlp(ln2(x))` with 4× MLP expansion; why residuals help gradients flow (gradient of identity = 1); final LayerNorm + LM head; optional weight tying (param savings computed).
- Stubs: `Block`, `GPT` (`__call__(idx, targets) -> (logits, loss)`), `count_params`.
- Tests: param count matches the formula; initial loss ≈ ln V; overfit one batch.

**s2-l08 AdamW, LR schedule, gradient clipping**
- Cover: L2-in-Adam vs decoupled weight decay (derive why they differ); which params to decay (matrices yes; biases, LayerNorm and embeddings: discuss); linear warmup + cosine decay formula, plotted; global-norm clipping $g \leftarrow g\cdot\min(1, c/\lVert g\rVert)$.
- Stubs: `AdamW`, `lr_at(step, warmup, max_steps, lr_max, lr_min)`, `clip_grad_norm(params, max_norm)`.
- Tests: hand-computed values; schedule endpoints; clipping preserves direction.

**s2-l09 Train, checkpoint, sample**
- Cover: the training script with config, periodic eval, checkpoints via `np.savez` / load, sampling (reuse s1-l13 logic); compare with stage 1 in **loss and bits per character**.
- Stub: `train_tf.py` skeleton, `save_checkpoint`, `load_checkpoint`.
- Tests: save → load round trip gives identical logits.
- **s2-boss:** reads `runs/s2/results.json`; passes if val loss ≤ 1.75 and below the s1 result (calibrate per §11). Shows the sample text.

```markdown
---
id: s1-l01

stage: s1
order: 1

::: goal
Turn raw Tiny Shakespeare text into integer batches: `x` of shape `(B, k)` (the previous k characters) and `y` of shape `(B,)` (the next character).
:::

::: notation
| Symbol | Meaning |
| --- | --- |
| V | vocabulary size: the number of distinct characters (65 for Tiny Shakespeare) |
| n | length of the encoded text (number of characters) |
| k | context length: how many previous characters the model sees |
| B | batch size: how many (x, y) examples per training step |
| `stoi` / `itos` | "string to integer" / "integer to string" mappings |
:::

::: concept
A neural network only takes numbers, so every character needs an integer id...

**Worked example.** Text `"hello"`, k = 3. Sorted vocabulary: `e, h, l, o` → ids `0, 1, 2, 3`.
Encoded: `h e l l o` → `[1, 0, 2, 2, 3]`.
Sliding a window of 3:

| x (context) | ids | y | id |
| --- | --- | --- | --- |
| h e l | [1, 0, 2] | l | 2 |
| e l l | [0, 2, 2] | o | 3 |

From a text of length n you get n − k pairs: here 5 − 3 = 2.

(Continue: the dtype choice, the position-based split and why, all pairs vs random starting indices, gathering windows with broadcasting, shown as shapes: `starts (B, 1)` + `offsets (1, k)` → `idx (B, k)`.)
:::

::: think
Q: Why sort the characters before numbering them?
A: `set()` order isn't guaranteed to be stable across runs or Python versions. Sorting makes the ids reproducible, so a saved model still matches the vocabulary when you reload it.
:::

::: think
Q: Why split train/val by position instead of shuffling all windows first?
A: Neighbouring windows overlap ("hell" and "ello" share 3 characters). If you shuffle, near-duplicates of val windows land in train, and val loss looks better than real generalization.
:::

::: think
Q: Building all n − k pairs up front vs sampling random starts per batch: what does each cost?
A: Up front: n·k integers (1.1M × 8 ≈ 9M, fine now, but 155M tokens × 256 in stage 3 is not). Random starts: only B·k per batch, from a single shared array. Random sampling scales.
:::

::: hint level=1
A batch is just B random starting positions. Everything else follows from those B numbers.
:::
::: hint level=2
Pick B starting positions with `rng.integers`, then build all B windows at once by **broadcasting** a column of starts against a row of offsets. The largest valid start matters: what is it?
:::
::: hint level=3
    starts  ← B random ints in [0, n − k)
    offsets ← [0, 1, ..., k−1]
    idx     ← starts as a column + offsets as a row      # (B, k)
    x       ← data at idx
    y       ← data at starts + k
:::

::: attempt
File: `workspace/stage1/data.py` — implement `build_vocab`, `encode`, `decode`, `train_val_split`, `get_batch`.
Check: `python -m course check s1-l01`
:::

::: solution
(reference code + a line-by-line WHY)
:::

::: breakit
Shuffle the windows before splitting, train in s1-l12, and compare val loss with the correct split. Expect the shuffled version to look better on "val" than it really is.
:::

::: recap
- Characters ↔ ids with sorted, reproducible mappings
- Position-based train/val split, and why
- Vectorized batch sampling with broadcasting, no Python loops
:::
```
